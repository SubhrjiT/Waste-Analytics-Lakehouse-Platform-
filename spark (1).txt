Spark Architecture:
In spark we have 3 main components
1) Driver Program
2) Cluster Manager
3) Worker Nodes

1) Driver Program - 
It is an entry point to spark engine.
In this we create SparkSession which creates the Jobs and stages

what is difference between sparkContext and SparkSession?
sparkContext - it is used to create the RDDs
SparkSession - it is combination sparkContext,sqlContext,hiveContext,
StreamingContext.

2) Cluster Manager:
Cluster manager calculates and allot the resources(How much RAM,no of cores) 
required to process the given jobs or stages.

3) Worker Nodes:
Cluster manager will launch the executors on Worker Nodes in executors 
tasks will get processed and the output is send to the driver program.

Jobs -----> Stages ------> Tasks

In spark architecture we have three components driver program,cluster manager,
worker nodes whenever we give any job to the driver program its stages and task 
are created and this is given to cluster manager,cluster manager will calculates
the resources reuqired to complete tasks and than launch the executors on worker node.
On worker nodes we will be having executors where the actual processing of tasks will takes place
and its ouput is send to driver program.

Transformation and Action in spark?

Transformation - 
Operation performed on RDD to get the new RDD is called Transformations.
two types of transformation - 
Narrow Transformation -
In Narrow Transformations there is no Shuffling of Data amoung the partitions.
example -  map,flapMap
Wide Transformation -
In wide Transformations there is Shuffling of Data amoung the partitions.
example - joins,groupByKey

Actions - 
It triggers the execution of transformations.
example - show(),count(),SaveAsTable()

why Spark is called as lazy evaluation?
until and unless action is called transformations are not executed.

what is catalyst Optimiser?
it is s rule based optimisation engine present in spark.
steps:
1- logical execution plan
it will create logical plan.
2- physical execution plan
it will take this logical plan and create one or many physical plans.
3- cost based optimisation
these physical plans are created on that 
cost based optimisation will be performed.
it will calculate the cost of each physical plan and select the physical plan
whose cost is less.
4- rule based optimisation
on selected physical plan rules based optimisation will be done.
pushfilter - this filtering the data at source.
column pruning - reading the required columns.
partition prunning - reading the required partitions.

AQE(adaptive query engine)?

what is difference between catalyst optimiser and AQE?
catalyst optimiser will optimise the queries before its execution 
whereas AQE will optimise the queries during the runtime.

3 - using coalesce instead of repartition 
to reduce the number of partitions?

coalesce - you can reduce the partitions using this coalesce,
you cannot increase the partitions using this.In colesce there is no shuffling
of data it will simple merge the adjacent partitions.


drawback of using coalesce?
it can cause data skewness

data skewness - 
when there is unequal size of partitions and the processing of 
partiitons is taking time this is called as data skewness.

How to overcome the data skewness?
to handle the data skewness we will use the salting technique.
salting technique-
we will add random hash values(salts) to primary key and create new primary key and 
again do the partitioning using newly  created primary key once this is processed 
newly generated primary key is dropped.


repartition -  this can increase and decrease the partitions.In repartiton
there is shuffling of data.

if i increase the partitions using the coalesce what will happen wether it will
increase the partition or it will simply execute without giving error or increasing the
partition or it will throw an error?
it will simply execute without giving error and without increasing the

what are the types of cluster in spark?
1 - All purpose cluster 
2 - Job Cluster
3 - Instance Pool Cluster

1 - All purpose cluster
this cluster is manually created according to required configuration.here we can 
decide the configuration(databricks runtime version,worker node configuration)
of the cluster.

2 - Job Cluster
you cannot create this manually, whenever you submit a job to process that job
this cluster will be created automatically once the processing of that is completed
this cluster will be terminated automatically.

3 - Instance Pool
In this pool(10 cluster) of clusters will be available whenever required you 
can select this pool in this which ever cluster is available will used for processing 
the job.
